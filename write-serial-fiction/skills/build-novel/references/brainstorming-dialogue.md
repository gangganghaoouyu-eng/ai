# 新书构建、逐轮构思与自由补充

在用户说“先陪我构思”、希望从一个想法逐步形成剧情，或普通章纲请求只有零散灵感时读取。沿用同一份当前构思，先形成粗略剧情，再根据回答展开；不要在用户尚想讨论时一次定完全部细纲。

## 新书启动与推进

- 用户已说“构建全新小说”或“帮我创建一本新小说”就已确定新书范围；题材未知时先问题材，题材已知则继续可跳过的书名或下一个重要缺口，不再问新书还是已有小说。
- 默认题材后接可选书名，再进入背景/世界观、主要人物、可选金手指及规则、核心矛盾与故事走向；依据回答动态调整。提前提供的设定、视角、结局等同时接入，不在后续机械再问。
- 书名未定就标“暂未命名”继续；金手指无、未定和已有分别处理，无外挂的小说不必填系统规则。用户明确希望先拆参考作品时先完成相关研究再接着构思。
- 草案优先达到本轮所需层级，从概念卡与故事雏形逐步到主体设定、大纲、卷纲和章纲，不要求一次补齐全部。

## 开始与选题

- 先复用用户已给的想法、适用资料和已回答事项。只有章纲启动词、没有故事内容且未明确新书或已有书时，先问构思新书还是已有剧情，并允许自由填写最想写的想法或场面；按下述交互规则选择界面，不要求先填写题材、人物、世界观全套资料。
- 默认每轮只问一个关键问题。优先选择会改变人物动机、冲突走向、主要选择、阶段终点或节奏的问题，顺序随回答变化，不机械执行固定问卷。用户要求加快或一起回答时才适量合并，并服从提问工具的数量限制。
- 把问题写得具体、容易回答；必要时给少量适用于当前故事的参考方向。明确允许自由回答，并说明“你也可以顺便补充其他人物、情节或设定想法”。不要把推荐选项当成用户的决定。
- 每次提问都接纳题外补充。用户选完选项后仍可在聊天中补充；自由填写的答案不必套选项。先处理补充中明确的创作要求，再设计下一问。

## 提问界面

依 [交互提问组件调用](ask-user-input.md) 选择并实际输出界面。支持 ask_user_input 时优先输出组件，每题都有自由输入提示；无该组件时使用适用的原生提问工具，再退回普通对话。把答案与后续聊天补充一并接入当前构思；没有答案时保留待定，不把未回答当成同意，也不反复发送同一问题。交互能力由宿主提供，不虚构本插件自有界面。

## 接入回答并继续

1. 理解当前答案和所有额外补充，更新受影响的人物动机、剧情因果、事件次序及节奏，保留其他仍适用的安排。用户明确改动替换对应旧安排；不要把局部修改扩大为整份推翻。
2. 区分用户已确定内容、助手建议、仍待确定内容。选择一个选项只确定该选项表达的方向，不等于同意全部后续设计；“没想好”不是授权将某个建议设为正式事实。
3. 根据进展选择下一步：追问一个关键问题；给两三种有具体影响的方案帮助比较；整理一版简短剧情雏形；或单独问“这一部分还有其他想补充的吗？”不在每轮机械追加补充询问，也不把多个新问题藏在一个问题里。
4. 有足够内容时先给粗略构思，说明从哪里开始、主要阻力、人物选择、大致结果和关键情绪变化；篇幅依当前范围调整，不默认铺开全卷或完整逐章细纲。阶段性整理已确定、建议和待定内容，只展示有用的更新，不每轮复制整套清单。
5. 新想法与已有安排冲突时，指出具体冲突及受影响节点，给融合或替换方向；小缺口可先提出标明来源的暂定建议。已发生的正文事实与未写的计划保持区别，不能悄悄改写既成事实。

## 模式切换与收束

- “按已有资料直接搭建”“直接生成框架/大纲/卷纲”：依已有材料、当前构思和指定范围直接生成，次要空缺标为建议，不再运行整套问卷。
- “先给我一版看看”：暂停提问，先给当前层级的暂定版本。已有核心想法就先形成草案，不把尚无名字或未选所有设定当成阻断。
- “整理成大纲/卷纲”：按指定层级整理，保留建议和待定状态，不追加结束确认。


- “直接生成章纲”：立即结束提问流程，依已有资料、当前构思和本轮要求生成；用已回答的内容，不重新调查一遍。次要空缺合理补成建议，核心冲突或根本缺乏故事输入时才提出最少的必要问题。
- “先别问，给我一版看看”：暂停提问，先给当前范围的暂定构思或章纲，不自动声称构思已经完成。
- “先陪我构思”：进入或返回逐轮对话，不因资料充分就忽略用户希望讨论的要求。
- “构思完成”：直接整理当前已构建的层级、建议和待定点；没有指定章纲时不擅自展开逐章细纲，不追加结束确认。
- “整理成章纲”“展开成几章细纲”：按指定范围直接整理，结合章纲卡与节奏规则展开，保留仍未确定事项的建议性质。

持续构思仅在当前对话中维护；需要跨会话继续时依据实际能读取的既有资料或用户带来的构思摘要，不承诺 skill 会自行永久记住全部对话。用户没有要求时，不默认写小说正文或建立额外存档。
