# 交互提问组件调用

在构思模式需要提问时读取。本文件把交互组件的调用格式直接纳入新书构建与章纲技能；无需要求用户另行选择 Ask User Input 技能。故事构思、追问和接入补充仍依本技能，界面由宿主渲染。

## 选择提问方式

1. 宿主已提供或当前会话已确认支持 GenUI 的 ask_user_input 组件时，优先依本文件直接输出交互提问。ChatGPT Work 中有对应组件能力说明，或当前对话已经成功显示同类提问框并收到答案，均可作为支持依据。
2. 无该组件、但有实际可用的 request_user_input 等原生提问工具时，遵守工具的真实参数和使用条件后调用。原生工具仅允许可选澄清时，只用于可选问题；必需输入用普通对话询问，不能套用下面的组件参数冒充工具参数。
3. 无适用交互能力、渲染失败、当前模式不支持或用户要求普通聊天时，用普通对话。不要把原始组件标记再次发送当成重试，不要求安装插件、登录或切换模式。

不要把“技能已加载”当成“提问框已显示”。满足组件使用条件且问题适合选项与自由输入时，实际输出组件，而不是只说明将要使用它。宿主能力不明确时不凭空承诺一定弹窗；显示样式由宿主决定。

## 问题与参数

- 默认每轮 questions 只放一个关键问题；用户希望一起回答时可增加，最多3个。
- question 写一个具体、会影响创作方向的问题。复用已回答内容，不用一个问题藏入多个新问题。
- options 使用2—4个简短、清楚的字符串，组件最多允许10个。选项帮助构思，不限定用户只能从中选择，也不把推荐方向当成已确认剧情。
- type 使用 single_select 或 multi_select。确定本轮主要任务等互斥方向用 single_select；题材元素、希望保留的场景等可以并存时优先 multi_select。
- 每个问题都必须有 free_text_placeholder。提示自由填写当前问题的其他答案，以及额外人物、情节、设定或约束；不要仅写“输入答案”。
- 不加入未定义字段，不使用 UUID Mode，不虚构自定义必填表单、文件上传或任意弹窗控制能力。组件只负责本轮问题，后续逐轮重新生成。

## 实际输出格式

先写一句简短、自然的话，承接已确定内容并允许自由补充。随后把下面形式的组件直接写进最终回复的正常内容，填入适合当前故事的真实问题。

下面的代码块仅用于说明调用方式；实际回复不能使用代码块、行内代码、引号或转义来包住组件，否则用户可能只看到代码。不要用普通 Markdown 列表代替已经可用的交互组件。

```text
genui{"ask_user_input":{"questions":[{"question":"这次你想从哪一种构思开始？","options":["构思一本新书","设计已有小说的后续剧情"],"type":"single_select","free_text_placeholder":"补充书名、剧情想法或其他设定"}]}}
```

“构建全新小说”或“帮我创建一本新小说”已明确新书范围，题材未知时直接使用题材问题，例如：

```text
genui{"ask_user_input":{"questions":[{"question":"你想构建哪一种题材的小说？","options":["校园恋爱","重生系统","末世求生"],"type":"single_select","free_text_placeholder":"填写其他题材、混合元素，也可补充人物、情节或设定想法"}]}}
```

题材已知且尚无书名信息时，可以询问可选书名：

```text
genui{"ask_user_input":{"questions":[{"question":"这本小说有已经想好的书名吗？","options":["已有书名","暂时没有，后面再定"],"type":"single_select","free_text_placeholder":"直接写出书名，或补充背景、人物、情节及其他想法；没有书名也可以继续"}]}}
```

没有书名、没想好或跳过时直接继续；只选择已有书名却未写名称时，不为名称阻断构思。用户已提供的信息同时接入，下轮不机械重复。例子帮助构思，不限定可选题材，不将参考题材自动写成默认。

已经确定“新书”后不要再次显示上述范围问题。依据用户已给内容选下一问，例如尚未确定背景时可用：

```text
genui{"ask_user_input":{"questions":[{"question":"你想把这本新书放在怎样的背景下？","options":["现代都市","修仙世界","末世世界","现代灵异"],"type":"single_select","free_text_placeholder":"写其他背景，或补充人物、情节想法"}]}}
```

示例只说明格式，不是固定问卷；背景、人物和情节已经提供时跳过对应问题。只有一句章纲启动词且新书/已有书范围尚未明确时，可以先用范围问题及自由输入入口收集方向；用户已明确新书或已有书时直接接着问，不能因尚无完整故事就强制回到普通文字问答。

输出组件后结束本轮回复；不在组件后继续解释、替用户回答、追加另一批问题或生成依赖未答内容的正式章纲。最终回复必须先用正常文字回答本轮必要的问题或报告已完成工作，再展示组件；不能把必要说明放到组件后面。

## 接收答案与继续

用户可能通过选项、自由填写、引用上一问题后附答案或普通聊天回答。识别为同一构思的回答，接入所有额外补充，再按当前进展追问、给可比较方案或整理粗略构思。自由文本和用户明确修订优先于选项中隐含的假设。

选择只确认选项表达的方向，未选择的选项不是创作要求；未回答和“没想好”保留待定，不自动视作同意。界面无法同时输入选项与额外文字时，照样接纳用户随后在聊天中的补充，不承诺每个客户端有相同输入布局。

用户说“直接生成章纲”“先别问，给我一版看看”“构思完成”或要求整理细纲时，立即按对应模式处理，不为使用组件额外追问。用户只问插件功能或界面来源时先回答，不无故启动故事问卷。

用户问调用来源时如实说明：新书构建、章纲流程与本文件的调用规则属于星栀插件；交互界面是宿主提供的组件。本插件包含调用指引，不声称新建了 MCP 工具、自有弹窗服务或独立界面程序。
