# 构建全新小说

把用户想法逐步形成能写下去的小说：先建立核心看点、人物目标和约束，再形成主体设定、大纲、卷纲及需要的章纲。依据实际材料和最新回答推进，不以固定问卷、齐全设定表或整齐章数替代构思。章纲与节奏的正式方法已完整合并到本技能，原章纲启动词直接进入本技能对应模式。

## 入口与模式

复用用户本轮、当前对话及实际可读取的相关资料。新书与已有小说的范围已明确时不再问范围；讨论本技能设计、询问功能或要求更新插件时先处理该请求，不启动故事采访。

| 用户表达 | 执行方式 |
| --- | --- |
| “构建全新小说”或“帮我创建一本新小说”（有无句号均可） | 默认逐轮构思；题材未知时直接问题材，已知时推进下一个关键缺口。 |
| “先陪我构思” | 进入或返回逐轮对话，资料充分也尊重讨论意图；无新书/已有书依据时才问范围。 |
| “按已有资料直接搭建”“直接生成框架/大纲/卷纲” | 根据已有材料和回答直接交付指定层级，不先问整套问卷；次要空缺补成明确的建议，根本缺少故事依据或核心冲突无法解决时只问最少的必要问题。 |
| “先给我一版看看”“先别问” | 暂停提问，按当前范围给暂定草案，保留建议与待定状态。 |
| “帮我设计章纲”“直接生成章纲”等 | 直达章纲规划；直接生成就用现有资料，只有零散想法时陪同构思，无故事依据才问构思范围。 |
| “整理成大纲/卷纲/前十章章纲”“构思完成” | 依据当前构思直接整理指定成果；“构思完成”未指定层级时整理已有层级和待定点，不擅自扩成全书逐章细纲，不追加结束确认。 |
| “只做设定”“只改人物/金手指/这一卷” | 保持指定范围；同步说明受影响的剧情，其他仍适用内容保留。 |

服从最新明确模式，随时允许切换。用户自主补充视为当前构思输入，不要求重新启动。

## 逐轮构建

先读 [逐轮构思与自由补充](references/brainstorming-dialogue.md)。需要提问时读取本插件的 [交互提问组件调用](references/ask-user-input.md)，满足宿主支持条件时实际输出组件，每题保留自由输入入口；无适用组件时用适用的原生工具或普通对话，不要求另选提问技能。

默认顺序为题材、可跳过的书名、故事背景/世界观、主要人物、可选金手指及规则、核心矛盾和故事走向，再逐步形成大纲、卷纲、章纲；每次只处理一个重要问题，依答案调整，不把各项一次塞进提问框。已有或提前补充的信息直接接入并跳过对应问题。

- 题材允许“校园恋爱”“重生系统”“末世求生”等自由表达和混合元素。区分主类型与附加机制；不强制男频/女频或默认恋爱、系统、CP。
- 已知题材但书名未知时可问有无书名。用户说没有、没想好、先跳过，立即继续；只表示已有书名却未写出时不为名称阻断构思，后续可自然补入。
- 依 [主体设定与人物规则](references/novel-foundation.md) 搭建相关背景、人设、关系和能力边界；无金手指不反复追问系统规则。
- 用户提供同类作品并希望先参考时先进入 [参考研究与原创方向](references/reference-research.md)，调用实际拆书技能；不先要求填完全部设定。
- 有足够材料就依 [阶段成果与持续修订](references/construction-output.md) 给一页概念卡或简短剧情雏形，再继续讨论，不等所有问题回答完。
- 区分用户已确定、助手建议、待定内容和已发生正文事实；选择一个方向仅确定其表达的内容，未答和“没想好”保留待定。

## 从主体框架到大纲、卷纲

依 [全书大纲与卷纲](references/whole-book-and-volumes.md) 建立长期目标、持续阻力、主角选择、阶段回报和后果，安排主线、重要支线、人物变化与结局方向。视角、阅读体验、预期体量和结束方向缺失且影响当前安排时再问，不强制一次补齐。

按 [阶段成果与持续修订](references/construction-output.md) 分批交付概念卡、主体设定、全书大纲、卷纲、章纲及细纲。长篇先建立宏观方向，再细化近期章节；用户明确要求全书逐章规划时按指定范围分批完成，不擅自缩减。章节数量与字数只是规划估计，不伪称实际统计。

## 章纲范围与依据

1. 在已选模式内识别构思、制定新章纲、展开已有细纲、安排连续章段、调整节奏或拆分章节。保持指定章数、时间点、视角、关键事件、必要台词和终点；明确允许自由设计时在范围内创作。
2. 读取 [既有小说资料](../write-serial-fiction/references/source-reading.md)。拟定章纲时，把已有章纲作为约束或待改对象，结合当前卷纲、适用阶段、相关人物世界设定和正文接点；旧事回响与伏笔先回读对应旧资料。用户已完整提供且仍适用的资料可复用。
3. 区分已发生事实、已确认计划、本轮新建议、构思中待定内容和人物认识。后期关系、能力和秘密不提前进入前期；草拟安排不更新阶段事实。用户明确修订优先；核心资料冲突无法解决时集中问一个关键问题，次要空缺合理安排。
4. 资料充分且用户要求生成时就继续，不要求先建立新书圣经或补齐全部旧章。只有故事想法时，依当前模式逐轮完善或直接给暂定计划，将新增具体安排标明为本轮方案；无章序依据时用暂定章名或“第1个规划章节”，不冒充正式章号。

## 从章段到场景

依 [节奏设计](references/pacing-design.md) 先确定章段目标、当前压力、准备或尝试、关键选择、实际兑现及余波，再依 [章纲卡与场景展开](references/chapter-cards.md) 分到章节。闭环可以跨章、嵌套或部分闭合；没有必要时不强制每章完整走一遍。

- 为每章确定一项主要变化，也允许并行次线。让阻力、对白、行动与后果支撑变化；不能只给“争执、解释、和解”等事件标签。
- 展开必须阅读的核心场景，压缩无关路程和重复事务。商议说明关键异议及回应怎样改变条件；战斗说明位置、行动与即时后果；独处和日常也可以通过选择、准备、关系或信息变化推进。
- 安排事件、信息、情绪、回报四种节奏。慢场景可以消化余波，快场景也要留下因果；不把每次平静都改成危机，不按固定章数安排反派、袭击和误会。
- 用已有能力、证据、资源及选择兑现回报；失败和新问题也要有前因。升级关注方法、难度、代价、对手、责任与关系，不能只放大数值或机械更换更强敌人。
- 以有效答复后的新内容推进谈话，情绪恢复可以滞后；不反复核对同一保证、伤势或已明确事项，不用一次拥抱完成全部修复。
- 先完成本章承诺的核心场景，再按 [章末钩子](../write-serial-fiction/references/chapter-hooks.md) 留具体承接。记录下一规划章怎样响应，不能用截断关键答案制造拖欠；明确终章时按终局收束。
- 依据本书章长预估场景分量。正式正文默认2700—3300字，章纲自身不执行该章长。多项重大场景装不下时先压缩重复、分清主次；若仍需改变指定章数或重大节点，说明具体冲突与拆分建议，不自行跨越授权。



## 衔接与交付

逐轮构思按进展交付一个问题、可比较方案或故事雏形；用户要求生成或整理时交付指定层级和深度。单章不扩成整卷，局部修改不推翻整书，章纲自身不受正文2700—3300字限制。

拆书与参考文风示范读取 [文章拆解与写法学习](../analyze-writing/SKILL.md)。参考研究任务默认做有范围的分析与创新方向，是否试写依用户请求；单独“帮我拆解”仍遵守拆书技能原有路径。本轮明确要求的参考机制可以作为本书创作建议，但不因此变成永久插件规则。

用户要求按设定或章纲写正文时读取 [小说正文](../write-serial-fiction/SKILL.md)，传递本书设定、人设、视角、当前阶段、章序接点、场景次序、关键选择、结果、知情边界和结尾承接。普通正文请求不额外输出整份构建问卷或章纲。

只在当前对话维护当前构思；跨会话依据实际可读取的材料或用户带来的构思摘要，不承诺自行永久记忆。对话构思不默认新增档案；用户请求文档或存档时遵守宿主文件保存规则。本书的事实与规划不写成插件通用规则，更新正式插件另依用户明确授权执行。
